# Screenshot Approval and Sanitization

No screenshots are included in the initial public case-study repository.

Screenshots may be added only after the client or authorized project owner explicitly approves public display. Approval should identify which screens may be shown and should be retained outside this public repository.

## Required sanitization

Every approved screenshot must:

- Be newly created using fictional demonstration data.
- Use a fictional business such as **Enterprise Demo Co.**
- Exclude real names, email addresses, phone numbers, addresses, signatures, account numbers, tax identifiers, employee details, customer details, and vendor details.
- Exclude real transactions, prices, analytics, document numbers, SKUs, filenames, and uploaded assets.
- Exclude client logos, private branding, browser bookmarks, open tabs, local paths, URLs, access tokens, notifications, and developer tools.
- Avoid showing private API paths, infrastructure details, or error messages.
- Be reviewed at full resolution before it is committed.
- Have metadata removed before publication.

## Suggested fictional screenshot set

If approved, a useful set would be:

1. An invoice editor and preview for Enterprise Demo Co.
2. A browser-fillable inventory count form.
3. An operations dashboard populated with clearly fictional values.
4. A flyer template containing fictional products and contact information.

Use PNG or WebP files with descriptive names and accessible captions in the main README. Do not add screenshots merely to fill space; each image should demonstrate a distinct product capability.
