# Public Publishing Checklist

Complete every item before making this repository public.

## Ownership and approval

- [ ] Confirm that the project may be discussed publicly at a high level.
- [ ] Confirm that **DocPrepEngine** is an acceptable public case-study name.
- [ ] Confirm that the “Individual responsibilities” section accurately reflects the repository owner’s work.
- [ ] Remove or revise any responsibility that cannot be personally supported.
- [ ] Obtain explicit approval before adding any screenshot or visual derived from the private application.

## Content review

- [ ] Confirm there is no production source code, copied markup, copied styling, prompt text, schema, configuration, or test fixture.
- [ ] Confirm there are no client names, logos, trademarks, private assets, or identifying project references.
- [ ] Confirm all people, companies, addresses, contact information, SKUs, document numbers, and financial values are fictional.
- [ ] Confirm there are no credentials, tokens, private URLs, environment values, account identifiers, or infrastructure names.
- [ ] Confirm the system diagrams are independently created and intentionally high level.
- [ ] Confirm file metadata and Git history contain no confidential information.

## Repository settings

- [ ] Use a new repository rather than changing the visibility of the private source repository.
- [ ] Initialize it from this sanitized folder only.
- [ ] Add an accurate short description and relevant topics.
- [ ] Disable unnecessary features such as issues or discussions if they will not be monitored.
- [ ] Review the public repository from a signed-out browser session after publication.

## Screenshot review, if approved

- [ ] Follow every requirement in `screenshots/README.md`.
- [ ] Inspect each image at full size.
- [ ] Remove metadata.
- [ ] Ask a second reviewer to check the image for accidental disclosure.

If any item is uncertain, keep the repository private until it is resolved.
